## Fresh Neon production

- Start independently on Neon PostgreSQL 18 from reviewed repository migrations
  001-020, with pgcrypto, explicit bootstrap ownership/search path, separate
  migrator/backend logins and tj_owner access, verified TLS and bounded connections.
- This is an accepted **fresh start**, not a transfer of historical Supabase data.
  Existing users register anew; old sessions/accounts/trades/investments were not
  imported. All new Neon records are protected. Validation fixtures were not copied
  into production, and Supabase is not a recovery target.
- Retain pg and application-owned JWT authentication; remove the confirmed unused
  Supabase wrapper/SDK and exclusive dependencies.

## Connection, initialization and authentication reliability

- Use explicit certificate/hostname verification, reject conflicting or weakening
  SSL URL options, preserve intentional loopback development and date-only parsing,
  and use a separate direct migration connection with explicit role selection.
- Serialize migrations, respect existing SQL transaction boundaries, atomically
  record successful files/checksums and preserve historical migration records.
  Add forward constraint validation and global/schema default-privilege hardening.
- Preserve policy-free RLS and server ownership checks. The trusted runtime assumes
  owner; this is not a least-privilege per-user database RLS model.
- Reject nonexistent-user sessions before protected work, clear invalid refresh
  cookies and stale client token/user/query state, share refreshes and ignore late
  responses across user changes. Network/server failures do not force invalidation.

## Fixes

- Correct proxy-shared rate-limit buckets. Use Railway's edge-overwritten X-Real-IP
  only when production Railway deployment metadata is present, and socket identity
  otherwise. Ignore forwarded chains, fail malformed headers into the peer bucket,
  normalize mapped IPv4 and IPv6 spellings, and aggregate IPv6 /64 addresses.
  Keep Express proxy trust disabled and preserve global 300/auth 20 requests per
  15 minutes, credentialed CORS and production cookie policy. This assumes HTTP-edge
  public ingress and a trusted private project network; no public TCP proxy is
  configured. Do not admit untrusted callers onto that private network.

- Allow the same CSV file in different owned accounts while retaining within-account
  duplicate protection; align preview feedback and forward migration 020.
- Reject quotes older than 96 hours or more than 5 minutes in the future. On failed
  refresh, use dated manual values instead of retaining an earlier quote as live;
  preserve explicit unavailable states. Live Finnhub integration remains included.
- Translate trade pagination into Hebrew and respect the selected text direction.
- The administrator company/broker catalogue, including casing requirements, is
  [Feature #7](https://github.com/OzAvrahami/trading-journal/issues/7), independently
  planned and excluded from this release.

# Trading Journal v1.0.0 — Trading and Investment Platform

The owner accepted v1.0.0 as Trading Journal's first stable release baseline.
It brings together the existing trading and investment platform through
`bebce992cc710df7407c551a8052bf7ad0e333c7`, plus the governance and release
documentation in the pending owner commit. The final pushed commit must be
verified before tagging. The historical `v0.2.0-redesign` and `v1.0.0-platform`
tags remain unchanged.

## Trading and accounts

- Manage open and closed trades with fees, net PnL, R-multiples, filtering,
  CSV export, trade details, and quick/full trade-entry workflows.
- Organize trading and investment accounts with account groups, participation
  settings, and explicit links to the investment portfolio ledger.
- Review the dashboard, trading calendar, equity curve, performance
  distributions, and analytics breakdowns using the user's timezone.
- Import TopstepX and Tradovate CSV files with account-scoped duplicate
  protection, import history, and bounded row diagnostics. Tradovate partial
  fills are grouped into logical trades; empty account-filter handling on
  trade loading is corrected.

## Journals, reviews, and rules

- Maintain journal entries and structured daily reviews, including what went
  well, improvements, next-session plans, emotions, and mistakes.
- Track trading rules and adherence checks, goals, strategies, and setups.
- Use English or Hebrew, RTL layouts, responsive navigation, themes, and
  saved preferences.

## Investment tracking and market valuation

- Track long-term investments separately from day-trading records through
  account-scoped overview, holdings, transactions, dividends, performance,
  and allocation views.
- Calculate cash, cost basis, realized and unrealized PnL, and recorded-price
  valuations from the investment ledger, with monetary totals grouped by currency.
- Use Finnhub quotes for eligible USD stocks and ETFs in current client-side
  valuation, with recorded manual prices as fallback and explicit unavailable
  states. Historical performance uses recorded transactions and manual prices.

## Security and maintenance

- Include JWT authentication and refresh sessions, server-side ownership
  checks, transactional authentication handling, request validation, rate
  limiting, and improved error handling.
- Include the existing Supabase public-schema access-hardening migration and
  security catalog in source. Its application to production was not verified
  during this governance work; no fresh security audit is claimed.
- Align GitHub metadata, labels, Status/Priority fields, and development views
  with Oz GitHub Development Standard v1. Prepare canonical Issue Forms with
  blank issues disabled, categorized release notes, and an explicit release
  process. These repository configuration files activate after the owner push.
- Record owner-confirmed Project workflow setup. Automation behavior was not
  independently tested. Reopened issues move to Ready, with the agreed manual
  fallback where necessary; native reopening support was not separately confirmed.

## Verification and scope limits

During preparation on 2026-09-10, Railway reported the client and API running
from `bebce992cc710df7407c551a8052bf7ad0e333c7`; the public homepage and API health
endpoint returned HTTP 200. Authenticated functionality, live database state,
applied migrations, and Finnhub behavior were not tested during this governance
work. Documentation and configuration checks passed; broad application test
suites were not rerun, and no workflow experiments or test issues were created.

Live valuation depends on server-side Finnhub configuration and provider
availability. No FX conversion, tax-lot accounting, broker synchronization,
TWR, or XIRR is included. Older README passages describing manual-only current
valuation predate the live-quote implementation.

All package versions remain 1.0.0. The Supabase-to-Neon migration is paused and
is not a completed release change. Future development issues, milestones, and
the next target version belong to the subsequent planning phase. Publication
does not itself deploy code or verify database state.

## Arithmetic and precision contract

Expected results below are calculated independently from transaction inputs,
not by calling application calculation helpers. API money totals are compared
at the documented two-decimal investment precision, absolute tolerance 0.005;
trade PnL values stored at four decimals use 0.00005; quantity/price/average-cost
values at eight decimals use 0.000000005. Exact examples with integer/cent
inputs must match exactly after their stated rounding. Ratios are fractions,
not percentage points. DATE strings and instant equivalence are exact checks.
No cross-currency sum is an expected financial metric.

## Authentication, boundaries and relationships

Signup must create only its user/session, with no accounts or portfolios until
explicit application requests. Authentication uses the real API against Neon.
Verify login, refresh rotation and replay rejection, logout, invalid cookies,
expired access and a correctly signed nonexistent-user subject. Controlled
transport/dependency failures must remain distinguishable from definitive 401s.
Client cancellation/cache tests supplement API behavior; they do not establish
interactive browser acceptance when no browser is connected.

User B must not read, update, delete, export or link A's account, trades,
journals, rules/checks, goals, strategies/setups, portfolios, instruments,
transactions, prices or import session/history. Lists must contain only the
signed-in user's data; foreign-ID filters may return empty or a safe 4xx, never
foreign data. Invalid relationships must leave no partially created records.

Create a trade-linked journal, structured daily review, followed/broken/
not-applicable rule checks, a dated goal, strategy and setup. Adherence excludes
not-applicable from its denominator: one followed and one broken means 50%.
Use real API create/read/update/delete for task-owned disposable records only.

## Calendar and UI expectations

Persist English/Hebrew preferences and Unicode text without corruption. Targeted
browser acceptance covers language switch, RTL, empty states, forms, navigation
and narrow/wide layouts; unavailable browser checks must remain open.

Use Asia/Jerusalem and America/New_York profile timezones. Explicit-offset trade
instants near midnight and DST must retain the same UTC instant; date filters,
calendar/day summaries and reviews use the selected user's local day. Include
Jerusalem spring DST (2026-03-27), New York repeated fall hour (2026-11-01),
month/year rollover and Sunday/Monday week boundaries. DATE-valued journals,
reviews and investment transactions must not shift. Invalid calendar dates and
reversed ranges must be rejected.

## Recovery oracle

After a task-owned pre-point journal marker is acknowledged, record server UTC
timestamp/LSN. A later task-owned marker must remain on the original validation
root but be absent from a new recovery-validation child forked at that point.
The pre-point marker and preceding task fixtures must be present in the child.
Use the real application API to read the restored state and compare schema,
ledger and security. Do not reset the root or assume recovery merges later writes.
Record elapsed times and the exact tested historical interval; no general RPO,
RTO or production-recovery commitment follows from this exercise.

## Execution clarifications (preserve the original expectations above)

The live catalog confirms trade entry/exit prices have eight decimal places;
trade PnL has four. One test incorrectly expected four trailing places in the
price's PostgreSQL text representation and was corrected, with no code change.
Unscoped day summaries deliberately suppress money totals for mixed EUR/USD
account scope; expect day counts/win rate and null money, rather than a combined
currency sum. Account-filtered calendar/summary retains its USD totals.

The stale-price failure led to an explicit 96-hour provider freshness ceiling,
allowing a long market-closure weekend, and a five-minute future-clock allowance.
Boundary regression inputs are exactly 96 hours old (accepted), 96 hours plus
one second old (rejected), and 301 seconds in the future (rejected). This is a
bounded observation-age rule, not proof of real-time exchange pricing or a
market-hours calendar. Manual values retain their explicit dates.
